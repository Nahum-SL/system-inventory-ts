01-instalar-servidor.txt
System Inventory: instalacion en la maquina oficial (Windows, red local)

Convencion de este archivo (la misma de tus help):
  =====  Secciones de pasos
  *****  Scripts y comandos para copiar
  #####  Conclusion o regla a recordar

Valores de ejemplo (usa SIEMPRE los mismos en todos los pasos):
  Carpeta del proyecto : C:\apps\e-yonda-ts
  Base de datos        : system_inventory_prod
  Usuario de la app    : inventario_app
  Usuario de respaldo  : inventario_backup
  Servicio             : SystemInventory
  Puerto               : 3000
  Carpeta de respaldos : D:\respaldos   (si no hay unidad D:, usa C:\respaldos
                                         y cambia la ruta en backup-db.ps1 y .backup.cnf)

NO escribas contrasenas reales en este archivo ni en ningun .txt que viaje en USB.
Genera claves de 24 o mas caracteres usando SOLO letras, numeros, "_" y "-"
(los caracteres  # " ' $ ` y espacios rompen el .env y el .backup.cnf).

====================================
0. ANTES DE SALIR DE LA LAPTOP
====================================
[ ] pnpm test en verde
[ ] pnpm build:all, pnpm start y pnpm smoke: las 7 comprobaciones
[ ] git tag v1.0.0 y git push --tags
[ ] El script "start" de package.json debe ser:
      node --env-file=.env.production dist/server.js
    (si solo lee .env, en el servidor no arrancara porque alli solo existe .env.production)
[ ] El archivo ops\windows\install-service.ps1 NO esta vacio (Length mayor que 0)

Lleva en un USB (no dependas de internet ni de que nssm.cc este arriba):
  - Instalador MSI de Node (misma version mayor que tu laptop)
  - Instalador de Git
  - Instalador de MySQL o MariaDB (el mismo motor que usas en la laptop)
  - nssm.exe (carpeta win64 del zip de NSSM 2.24)
  - El .env.production ya preparado (NO va por Git)

====================================
1. RED Y EQUIPO
====================================
1.1 IP reservada en el router (reserva DHCP por la MAC de la maquina).
    Anotala: es el PUBLIC_APP_URL. Los QR dependen de esa IP: defínela ANTES de imprimir etiquetas.
    Un nombre .local es poco fiable en Android: usa la IP.

1.2 Perfil de red Privado (con perfil Publico Windows bloquea las conexiones entrantes):

*******************
Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private
*******************
   (cambia "Wi-Fi" por el InterfaceAlias que muestre el primer comando; si va por cable, "Ethernet")

1.3 Firewall: solo el puerto de la app, solo perfil Privado, solo la red local:

*******************
New-NetFirewallRule `
  -DisplayName "Inventario 3000" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 3000 `
  -Action Allow `
  -Profile Private `
  -RemoteAddress LocalSubnet
*******************

1.4 Que la maquina no se duerma:

*******************
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
*******************

1.5 Manual, en Configuracion de Windows:
    - Windows Update: define el "horario activo" (que no reinicie en plena jornada).
    - Fecha, hora y zona horaria correctas (Lima, UTC-5) y sincronizadas.
    - Si hay antivirus: excepcion para la carpeta C:\apps\e-yonda-ts y node.exe.
    - NO abras puertos en el router (sin port forwarding): el sistema no sale a internet.

####################
Regla: sin perfil Privado, la regla de firewall no sirve de nada.
####################

====================================
2. SOFTWARE
====================================
2.1 Node con el instalador MSI oficial (queda en C:\Program Files\nodejs).
    NO uses nvm, fnm ni Volta aqui: el servicio corre como SYSTEM y no los encuentra.
2.2 Git.
2.3 pnpm:

*******************
npm install -g pnpm
node -v
pnpm -v
(Get-Command node).Source      # debe empezar por C:\Program Files\nodejs
*******************

2.4 MySQL o MariaDB (el mismo motor que en la laptop). Anota el nombre del servicio:

*******************
Get-Service *mysql*, *mariadb*
SELECT VERSION();               # dentro del cliente SQL: confirma motor y version
*******************

====================================
3. BASE DE DATOS
====================================
En el cliente SQL como root (mysql -u root -p). Claves nuevas, NO las de tu laptop:

*******************
CREATE DATABASE system_inventory_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'inventario_app'@'localhost' IDENTIFIED BY '<CLAVE-APP>';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON system_inventory_prod.* TO 'inventario_app'@'localhost';

FLUSH PRIVILEGES;

SHOW GRANTS FOR 'inventario_app'@'localhost';
*******************

- La app NO usa root. Los permisos CREATE, ALTER, INDEX, DROP y REFERENCES son los que
  necesitan las migraciones (pnpm migrate:prod) y se pueden quitar mas adelante si quieres.
- Que MySQL escuche solo en localhost (no abras el 3306 en el firewall).
- Si el servicio no se conecta con "Access denied" usando DB_HOST=localhost, crea tambien
  el usuario para '127.0.0.1' (mismo CREATE USER y GRANT cambiando el host).

(Solo si MySQL da errores raros de privilegios tras una instalacion rota:
   REPAIR TABLE mysql.global_priv;   CHECK TABLE mysql.global_priv;
 es una recuperacion puntual de MariaDB, no forma parte de la instalacion normal.)

====================================
4. CODIGO Y CONFIGURACION
====================================
*******************
cd C:\apps
git clone <URL-DEL-REPOSITORIO> e-yonda-ts
cd e-yonda-ts
git checkout v1.0.0
pnpm install
*******************

pnpm install debe hacerse CON devDependencies (las migraciones usan tsx). No uses --prod.

Genera el JWT_SECRET (uno nuevo, distinto al de desarrollo y pruebas):

*******************
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
*******************

Crea .env.production en la raiz del proyecto (usa .env.production.example como guia):

*******************
NODE_ENV=production
PORT=3000
CORS_ORIGIN=http://<IP-RESERVADA>:3000
PUBLIC_APP_URL=http://<IP-RESERVADA>:3000

DB_HOST=localhost
DB_PORT=3306
DB_NAME=system_inventory_prod
DB_USER=inventario_app
DB_PASSWORD=<CLAVE-APP>

JWT_SECRET=<el-que-generaste>
JWT_EXPIRES_IN=28800

# Solo para el primer seed. Se borran despues (seccion 11).
ADMIN_USERNAME=admin
INITIAL_ADMIN_PASSWORD=<clave-larga-de-al-menos-12-caracteres>
ADMIN_DNI=<8 digitos>
ADMIN_NOMBRES=<nombres>
ADMIN_APELLIDOS=<apellidos>
ADMIN_TELEFONO=<9 digitos>
ADMIN_EMAIL=<correo>
*******************

- Sin barra final en las URLs.
- En produccion no debe existir un .env de desarrollo en esta maquina.
- Protege el archivo (solo Administradores y el sistema; el servicio corre como SYSTEM).
  Se usan SIDs porque los nombres de grupo cambian segun el idioma de Windows:

*******************
icacls .env.production /inheritance:r /grant:r "*S-1-5-32-544:F" "*S-1-5-18:F"
*******************

====================================
5. BUILD Y DATOS
====================================
*******************
pnpm build:all
Test-Path .\.env.production, .\dist\server.js      # ambas True
pnpm migrate:prod
pnpm seed:prod
*******************

Si falta una variable, el error nombra la variable (nunca muestra valores).
Si el seed dice "ya existe", la cuenta ya estaba creada y no se toca nada.

====================================
6. PRUEBA EN PRIMER PLANO
====================================
*******************
netstat -ano | findstr :3000       # debe salir vacio
pnpm start
*******************

En OTRA terminal:

*******************
pnpm smoke http://localhost:3000   # deben pasar las 7 comprobaciones
*******************

Despues detén el proceso con Ctrl+C. Si esto falla, NO sigas con el servicio.

====================================
7. SERVICIO DE WINDOWS (NSSM)
====================================
7.1 Instalar NSSM (con el nssm.exe del USB, o descargandolo):

*******************
New-Item -ItemType Directory -Force C:\tools\nssm | Out-Null
Copy-Item <ruta-del-USB>\nssm.exe C:\tools\nssm\nssm.exe
C:\tools\nssm\nssm.exe version
*******************

   Con internet: Invoke-WebRequest https://nssm.cc/release/nssm-2.24.zip -OutFile $env:TEMP\nssm.zip
   y luego Expand-Archive y copiar win64\nssm.exe.

7.2 Comprobaciones previas (PowerShell COMO ADMINISTRADOR, dentro de la carpeta del proyecto):

*******************
(Get-Item .\ops\windows\install-service.ps1).Length     # mayor que 0
(Get-Command node).Source                               # C:\Program Files\nodejs
netstat -ano | findstr :3000                            # vacio
*******************

7.3 Instalar el servicio:

*******************
powershell -ExecutionPolicy Bypass -File .\ops\windows\install-service.ps1
*******************

Debe imprimir "Instalando el servicio 'SystemInventory' desde ..." y al final
"Servicio 'SystemInventory' instalado e iniciado". Si no imprime NADA, el script esta vacio.

7.4 Comprobar:

*******************
C:\tools\nssm\nssm.exe status SystemInventory     # SERVICE_RUNNING
pnpm smoke http://localhost:3000                  # 7 comprobaciones
Get-Content .\logs\error.log -Tail 20             # sin errores
Get-Content .\logs\out.log -Tail 20               # mensaje de arranque
*******************

Para escribir solo "nssm" en esta ventana:  $env:Path += ";C:\tools\nssm"

====================================
8. PRUEBAS DE RESISTENCIA
====================================
A) Se levanta solo si el proceso muere (mata solo el proceso del servicio):

*******************
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object CommandLine -like "*dist\server.js*" |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Start-Sleep 8
C:\tools\nssm\nssm.exe status SystemInventory     # SERVICE_RUNNING otra vez
pnpm smoke http://localhost:3000
*******************

B) Reinicio tras actualizar (lo que haras en cada version nueva):

*******************
C:\tools\nssm\nssm.exe restart SystemInventory
pnpm smoke http://localhost:3000
*******************

C) (OPCIONAL, solo el primer dia, antes de cargar datos reales) Aviso de fallo claro:
   renombra .env.production a .env.production.bak, arranca el servicio, mira
   logs\error.log (debe nombrar las variables invalidas) y DEVUELVE el archivo a su nombre.
   Mientras falte, el servicio se reinicia cada 5 segundos.

====================================
9. ORDEN DE ARRANQUE CON LA BASE DE DATOS
====================================
Si al reiniciar la maquina la app arranca antes que MySQL, falla la conexion.
Con el nombre exacto que mostro Get-Service (por ejemplo MySQL80 o MariaDB):

*******************
C:\tools\nssm\nssm.exe set SystemInventory DependOnService <NombreDelServicioDeLaBD>
C:\tools\nssm\nssm.exe restart SystemInventory
*******************

====================================
10. DESDE UN CELULAR (valida firewall y red)
====================================
En el celular (misma WiFi, datos moviles apagados):
  1. Abre  http://<IP-RESERVADA>:3000/login
  2. Desde otra PC o celular con Node:  pnpm smoke http://<IP-RESERVADA>:3000
  3. Crea un activo de prueba, abre su ficha y escanea su QR con la camara: debe abrir
     la ficha (pidiendo login si no hay sesion).

Si el celular no carga: perfil de red (1.2), regla de firewall (1.3) o aislamiento de
clientes del router (probar con otra banda 2.4/5 GHz).

11. SEGURIDAD DEL PRIMER INGRESO
====================================
  1. Entra como admin y cambia la contraseña en "Mi cuenta".
  2. En .env.production BORRA estas lineas:
       INITIAL_ADMIN_PASSWORD, ADMIN_USERNAME, ADMIN_DNI, ADMIN_NOMBRES,
       ADMIN_APELLIDOS, ADMIN_TELEFONO, ADMIN_EMAIL
  3. C:\tools\nssm\nssm.exe restart SystemInventory
  4. Crea las cuentas de los usuarios desde el panel (Usuarios), no desde la base de datos.

====================================
12. RESPALDO
====================================
12.1 Usuario de la base solo para respaldar (SQL como root):

*******************
CREATE USER 'inventario_backup'@'localhost' IDENTIFIED BY '<CLAVE-BACKUP>';
GRANT SELECT, SHOW VIEW, TRIGGER ON system_inventory_prod.* TO 'inventario_backup'@'localhost';
FLUSH PRIVILEGES;
*******************

12.2 Archivo de credenciales, FUERA del repositorio: D:\respaldos\.backup.cnf

*******************
[client]
user=inventario_backup
password=<CLAVE-BACKUP>
host=localhost
*******************

Protegelo (el script corre como SYSTEM):

*******************
icacls D:\respaldos\.backup.cnf /inheritance:r /grant:r "*S-1-5-32-544:F" "*S-1-5-18:F"
*******************

12.3 Ruta de mysqldump. Busca el ejecutable real (MariaDB puede llamarlo mariadb-dump.exe):

*******************
Get-ChildItem "C:\Program Files\MySQL","C:\Program Files\MariaDB*" -Recurse `
  -Include mysqldump.exe,mariadb-dump.exe -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty FullName
*******************

Pon esa ruta en $MysqlDump dentro de ops\backup\backup-db.ps1. Si mysqldump responde
"unknown option '--no-tablespaces'" (MariaDB), quita esa opcion del script: solo hace
falta en MySQL 8.

12.4 Respaldo manual de prueba (PowerShell como administrador):

*******************
pnpm backup:db
Get-ChildItem D:\respaldos\inventario | Sort-Object LastWriteTime -Descending | Select-Object -First 3
*******************

12.5 Tarea diaria (dentro de la jornada, con la maquina encendida):

*******************
schtasks /Create /TN "Respaldo inventario" /SC DAILY /ST 18:30 /RU SYSTEM `
  /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\apps\e-yonda-ts\ops\backup\backup-db.ps1"

# Si la maquina estaba apagada a esa hora, que lo ejecute apenas pueda:
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable
Set-ScheduledTask -TaskName "Respaldo inventario" -Settings $settings

schtasks /Run /TN "Respaldo inventario"     # lanzarla ahora para comprobar
*******************

12.6 Segunda copia: un respaldo en el mismo disco no te protege de un fallo del disco,
un robo o un incendio. Disco externo (semanal) o carpeta sincronizada. Si el archivo sale de
la empresa, cifralo con 7-Zip (-p): contiene datos personales.

12.7 Probar la restauracion (hoy y una vez al mes), SIEMPRE en una base temporal:

*******************
Expand-Archive "D:\respaldos\inventario\<archivo>.sql.zip" -DestinationPath "D:\respaldos\restore" -Force
mysql -u root -p -e "CREATE DATABASE restore_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
cmd /c "mysql -u root -p restore_test < D:\respaldos\restore\<archivo>.sql"
mysql -u root -p -e "SELECT COUNT(*) FROM restore_test.activos; DROP DATABASE restore_test;"
*******************

(Si "mysql" no esta en el PATH, usa la ruta completa de mysql.exe.)
